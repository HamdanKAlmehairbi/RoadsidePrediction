   ```python
   def rand_routes(self) -> None:
       netfile = self.config["net-file"]
       self.rand_route_args["n_routefiles"] = 1
       if self.horizon is not None:

       if self.time_of_day:
           # Sample demand from time-of-day range: AM rush (500-700), midday (200-300), PM rush (400-600)

           period = random.choice(["am_rush", "midday", "pm_rush"])
           vplph_ranges = {
               "am_rush": (500, 700),
               "midday": (200, 300),
               "pm_rush": (400, 600),
           }
           lo, hi = vplph_ranges[period]
           vplph = random.randint(lo, hi)

           netfile=netfile,
           path=self.path,
           number_of_lanes=self.num_of_lanes,
           **self.rand_route_args
       )
   ```
   This is the simpler per-episode approach (recommended in research doc). Each episode gets a different demand level sampled from one of three time-of-day profiles.

**Part B: Time encoding in SumoEnv (env.py)**

1. In SumoEnv.__init__ (which was modified in 04-02 to read alpha), also read use_time_encoding:
   ```python
   def __init__(self, config):
       self.alpha = config.get("alpha", 1.0)
       self.use_time_encoding = config.get("use_time_encoding", False)

   ```

2. Add `import math` at top of env.py.

3. Override `observation_space` property to add 2 features when time encoding is active:
   ```python
   @property
   def observation_space(self) -> spaces.Space:
       first = self.kernel.tls_hub.index2id[0]
       base = self.kernel.tls_hub[first].observation_space
       if self.use_time_encoding:
           n = base.shape[0] + 2
           low = np.concatenate([base.low, np.array([-1.0, -1.0], dtype=np.float32)])
           high = np.concatenate([base.high, np.array([1.0, 1.0], dtype=np.float32)])
           return spaces.Box(low=low, high=high, dtype=np.float32)
       return base
   ```

4. Modify `_observe()` to append sin/cos time features AFTER ranking (so rank indices 10-13 are unaffected):
   ```python
   def _observe(self) -> Dict[Any, np.ndarray]:
       obs = {tls.id: tls.get_observation() for tls in self.kernel.tls_hub}
       if self.ranked:
           self._get_ranks(obs, halted=False)
           self._get_ranks(obs, halted=True)
       # Append time encoding AFTER ranking (so rank indices 10-13 are correct)
       if self.use_time_encoding:
           horizon = self.horizon or 3600
           t = self.step_counter
           sin_t = math.sin(2 * math.pi * t / horizon)
           cos_t = math.cos(2 * math.pi * t / horizon)
           for tls_id in obs:
               obs[tls_id] = np.append(obs[tls_id], [sin_t, cos_t]).astype(np.float32)
       # Clean NaN and Inf
       for tls in obs:
           for i in range(len(obs[tls])):
               feature = obs[tls][i]
               if feature == np.nan or feature == float('-inf'):
                   obs[tls][i] = 0.0
               elif feature == float('inf'):
                   obs[tls][i] = 1.0
       return obs
   ```

   Why AFTER ranking: `get_observation()` returns 10 features (N_UNRANKED_FEATURES=10). `_get_ranks` writes at indices 10-13 (LOCAL_RANK, GLOBAL_RANK, LOCAL_HALT_RANK, GLOBAL_HALT_RANK). If time encoding were appended BEFORE ranking, indices 10 and 11 (our sin/cos values) would be overwritten by rank values. Appending AFTER ranking places sin/cos at indices 14-15, leaving all existing indices intact.

5. Note on _get_reward / _get_all_rewards: The reward uses `obs[LANE_OCCUPANCY]` (index 0) and `obs[HALTED_LANE_OCCUPANCY]` (index 1). These indices are unchanged by time encoding appended at the end. No changes needed to reward computation.

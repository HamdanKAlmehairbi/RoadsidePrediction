<objective>
Implement FedProx aggregation as a PPOTorchPolicy subclass with proximal term in the loss function, and wire it into FedPolicyTrainer.

Purpose: FedProx keeps local model weights close to the global model during training, improving convergence on heterogeneous clients (different intersection types). This is a core research extension for publishable comparison against vanilla FedAvg.

Note: Verifying that "FedProx converges faster than FedAvg" requires a post-execution evaluation campaign using the Phase 3 experiment runner (run both FedAvg and FedProx configs, compare reward curves). That comparison is out of scope for this implementation plan but enabled by it.

Output: FedProxPPOTorchPolicy class and updated FedPolicyTrainer that uses it when fedprox_mu > 0.
</objective>

2. `set_fedprox_mu(self, mu: float) -> None`: Store mu value.

3. `store_global_weights(self) -> None`: Snapshot current model weights as the global reference:
   ```python
   self._global_weights = {
       k: v.detach().clone()
       for k, v in self.model.state_dict().items()
   }
   ```

4. `loss(self, model, dist_class, train_batch)`: Override PPOTorchPolicy.loss().
   - Call `base_loss = super().loss(model, dist_class, train_batch)` to get standard PPO loss.
   - If `self._fedprox_mu > 0.0` AND `self._global_weights is not None`:
     - Compute proximal term: iterate `model.named_parameters()`, for each param that exists in `self._global_weights`, accumulate `(mu/2) * sum((param - global_w)**2)`.
     - Use `torch.tensor(0.0, device=next(model.parameters()).device)` as initial accumulator.
     - Move global weights to param device with `.to(param.device)`.
     - Return `base_loss + proximal_term`.
   - Otherwise return `base_loss` unchanged.

2. Modify `__init__` to accept `fedprox_mu` parameter:
   - Add `fedprox_mu: float = 0.0` as a keyword argument (after `fed_step`).
   - Store `self.fedprox_mu = fedprox_mu`.
   - AFTER `super().__init__(...)` call, override `self.policy_type`:
     ```python
     if self.fedprox_mu > 0.0:
         self.policy_type = FedProxPPOTorchPolicy
     ```
   - This works because `__load_policy_type()` runs in `BaseTrainer.__init__()` (sets PPOTorchPolicy), but `on_policy_setup()` runs later at train time and reads `self.policy_type`. So overriding after super().__init__() is correct timing.

3. Modify `on_data_recording_step()`: After the existing aggregation block (lines 91-97 where `set_weights(new_params)` is called for each policy), add FedProx weight storage:
   ```python
   if aggregate_this_round:
       policy_dict = {policy_id: self.ray_trainer.get_policy(policy_id)
                      for policy_id in self.policies
                      if policy_id != GLOBAL_POLICY_VAR}
       new_params = self.fedavg(policy_dict)
       for policy_id in self.policies:
           policy = self.ray_trainer.get_policy(policy_id)
           policy.set_weights(new_params)
           # FedProx: store global weights AFTER setting new aggregated params
           if self.fedprox_mu > 0.0 and hasattr(policy, 'store_global_weights'):
               policy.set_fedprox_mu(self.fedprox_mu)
               policy.store_global_weights()
   ```
   The order is critical: (1) fedavg, (2) set_weights, (3) store_global_weights. This ensures the proximal term pulls toward the fresh global, not stale local weights.

Do NOT modify `on_policy_setup()` — it already uses `self.policy_type` which we override in __init__.
